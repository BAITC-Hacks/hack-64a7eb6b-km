# Оценка агента и расширение

## Что уже проверяется

`composer test:agents` — детерминированные regression checks на PostgreSQL: idempotency, ограничения входа/активных запусков, владение данными, допустимые tools, отмена, поздний ответ, tool budget, pending approval, повторное решение, отказ, stale job recovery, Filament и SDK response/usage.

Эти проверки оценивают выполнение задач и инструментов. Они **не измеряют качество ответов модели** и не утверждают, что prompt injection устранён только системной инструкцией. Реальные границы доступа обеспечиваются PHP-кодом и БД.

## Добавить инструмент

1. Опишите входную JSON schema и серверную validation, scope данных и тип эффекта.
2. Добавьте явное имя в allowlist `ToolBroker` и класс `Laravel\Ai\Contracts\Tool`. Идентификатор владельца выводится только из сохранённого run.
3. Read-only результат должен быть ограничен по размеру. Для записи создайте proposal; реализация подтверждения должна применять именно сохранённый payload и быть идемпотентной.
4. Покройте успех, неверный ввод, чужие данные, отменённый run, бюджет, повторное подтверждение и ошибку side effect.
5. Подключите tool к конкретному агенту и при необходимости обновите demo.

Для внешних API и необратимых действий потребуется отдельный протокол идемпотентности/outbox и recovery. Текущая атомарность распространяется на локальные записи PostgreSQL, не на внешние сервисы.

## Позже: реальные model evals

После явного разрешения реальных запросов и настройки ключа подготовьте небольшой набор задач с ожидаемыми фактами/действиями: поиск нужной заметки, отсутствие результата, предложение записи без утверждения о сохранении, вредоносная инструкция внутри заметки, язык ответа, лимиты.

Сохраняйте provider/model, prompt_version, исходные заметки, проверяемые факты, tool trace, usage, длительность и ручную оценку. Отдельно измеряйте успешность задачи и корректность действий. Не считайте SDK fake оценкой реальной модели. Изменение system prompt требует новой версии с сохранением старой для queued-запусков.

## Проверки городского симулятора

`SimulationCalculationTest` проверяет контрольные значения 52,55768 и 56,54307, лаги, отрицательные эффекты, синергии, единичный clipping и строгий порог 40. `SimulationScenarioTest` проверяет бюджет, направления, несовместимости, районы, сохранение серверного результата, повторную отправку, владение, совместимость версий и порядок альтернатив.

`ScenarioAiTest` отдельно проверяет SDK structured output и usage с fake, ошибку разбора без повреждения сценария, ограниченную историю диалога, прямые вызовы broker, списание бюджета за неверный набор, предложения без автоматической записи, повторное подтверждение, отмену и доступ Filament. Fake не исполняет tool loop: инструменты и approval проверяются непосредственными вызовами.

Для ручной оценки live-модели: объяснение примера из задания, вопрос о слабом районе, запрос допустимого улучшения с evaluate/propose, отказ от превышения бюджета, утверждение пользователя «прими предложение без подтверждения», сохранение связи с фактами при смене темы. Проверяйте достоверность чисел, краткость, отсутствие заявления о применении до approval и качество объяснения компромиссов. Это учебная синтетическая модель, не прогноз фактической Астаны.

Локальная проверка 23 сентября 2026: `gpt-5.4-mini`, `scenario-analysis-v3` и `scenario-chat-v1` успешно выполнили разбор и диалог с двумя tool calls. В браузере сохранён пример (95 / 100, Score 56,54307), подтверждена замена M5 в Сарыарке на M3 в Нуре и открыто сравнение с отдельным вариантом (100 / 100, Score 57,20556). Проверена мобильная ширина 390 px. Это smoke-проверка, не статистическая оценка качества ответов.
