# HACKALEM.AI

Приложение для работы с AI-агентами: задачи, инструменты, история запусков и подтверждение изменений.

**Стек:** PHP 8.4+, Laravel 13, PostgreSQL 18, React 19, Inertia 3, TypeScript, Tailwind 4, Filament 5. Laravel AI SDK отвечает за модели и tool loop; Laravel Boost — за MCP, документацию и инструкции coding-агентам.

По умолчанию включён **локальный demo-режим**: ключ не нужен, запросы к AI-провайдерам не отправляются. Demo использует настоящую очередь, PostgreSQL, инструменты, журнал и подтверждения; текст ответа формирует детерминированный сценарий.

## Быстрый старт

Нужны PHP с `pdo_pgsql`, `intl`, `bcmath`, `mbstring`, `dom`, `xml`, `zip`, `gd`, `pcntl`, Composer 2, Node 22.12+ и PostgreSQL.

```bash
# Один раз: создайте отдельные базы (или через интерфейс Herd).
createdb -h 127.0.0.1 -U postgres hackalem
createdb -h 127.0.0.1 -U postgres hackalem_testing

cp .env.example .env
# При необходимости измените DB_HOST/DB_PORT/DB_USERNAME/DB_PASSWORD в .env.
composer setup

composer dev
```

`composer setup` устанавливает зависимости, создаёт ключ только если его ещё нет, применяет миграции, создаёт демо-администратора и собирает frontend. Существующие базы не очищаются. В текущем локальном окружении зависимости и обе базы уже подготовлены.

**Демо-вход:** `admin@hackalem.test` / `admin`. Данные показаны под заголовком страницы входа в Filament. При `DEMO_ADMIN_ENABLED=true` в локальном окружении эта учётная запись создаётся при подготовке проекта, `php artisan db:seed` и открытии `/admin/login`. Если её удалили или изменили пароль/права, следующий вход на страницу восстановит демо-доступ. Повторные вызовы сохраняют ту же учётную запись без дубликатов. Для отключения установите `DEMO_ADMIN_ENABLED=false`; в production создание и подсказка выключены независимо от флага.

Для отдельной личной учётной записи доступна команда `php artisan app:user developer@example.test --name=Developer --admin` со скрытым вводом пароля.

- Приложение: [localhost:8000](http://localhost:8000), после входа — `/runs`.
- Filament: [localhost:8000/admin](http://localhost:8000/admin), только для пользователей с ролью `super_admin` и подтверждённым email.

В разделе «Управление доступом» доступны пользователи, роли и каталог разрешений. В карточке пользователя можно менять имя, email и пароль, назначать роли и дополнительные разрешения. `super_admin` — единственная роль админпанели, также получающая все права фронтенда. Демо-администратору назначается именно она. Остальные роли работают только на фронтенде: «Наблюдатель» — просмотр, «Участник» — действия со своими запусками. Новым пользователям назначается «Участник». Его разрешения можно менять, но название и удаление защищены. Демо-аккаунт и системная роль `super_admin` защищены от изменения в панели; последнего супер-администратора нельзя удалить или лишить доступа.

Права из группы «Рабочее пространство» действуют на React/Inertia-страницах: просмотр своих запусков и заметок, создание, отмена, подтверждение и отклонение предложений. Для действий нужен также доступ к просмотру. Меню и кнопки учитывают разрешения, а каждый запрос проверяется на сервере. «Наблюдатель» не может создавать запуски или подтверждать записи. Даже `super_admin` не получает доступ к чужим запускам через пользовательские маршруты. Разрешения для входа и управления админпанелью не назначаются отдельно: эти возможности определяются ролью `super_admin`.

- `composer dev` запускает web, Vite, worker очередей `agents,default` и scheduler. При изменении PHP-кода runtime перезапускайте worker / `composer dev`.
- Если порт занят, задайте одинаковый порт в `APP_URL` и `SERVER_PORT` в `.env`. В текущем окружении выбран свободный **8007**. Vite для этого локального HTTP-сценария использует HTTP на loopback без автоматического сертификата Herd.
- Обычная регистрация доступна; ссылки подтверждения email при `MAIL_MAILER=log` находятся в локальном `storage/logs/laravel.log`.

## Проверка сценария

1. Отправьте задачу в `/runs`.
2. Дождитесь статуса «Завершён» и изучите события `tool.started` / `tool.completed`.
3. Агент предложит заметку. До подтверждения её нет в таблице `notes`.
4. Нажмите «Подтвердить запись» или «Отклонить». Повторное нажатие не создаёт дубликаты.
5. Вернитесь в список: подтверждённая заметка доступна следующим запускам того же пользователя.

## Подключение AI позже

Добавьте собственный ключ **только в игнорируемый `.env`**, не в Git и не в чат. Затем установите:

```dotenv
AGENT_DRIVER=laravel
AGENT_PROVIDER=openai
AGENT_MODEL=gpt-5.4-nano
```

Имя переменной ключа — `OPENAI_API_KEY`. Выполните `php artisan config:clear`, `php artisan app:doctor` и перезапустите worker. Сам `app:doctor` AI-запросов не делает. Возврат `AGENT_DRIVER=demo` выключает live-адаптер, в том числе для ранее поставленных live-задач.

Модель задаётся конфигурацией, доступность зависит от аккаунта. Другие провайдеры настраиваются в `config/ai.php` и должны поддерживать tools. Реальный API в рамках первоначальной подготовки не вызывался.

## Проверки и инструменты разработки

```bash
php artisan app:doctor
composer test:agents       # Жизненный цикл, инструменты, права и approvals
composer test               # Весь PHP-набор на PostgreSQL
composer types:check        # Larastan, level 7
npm run types:check
composer ci:check           # Все проверки + production build
composer boost:refresh    # Boost: инструкции, skills и MCP
```

Тесты принудительно используют `hackalem_testing`. Они не используют SQLite, базу приложения или реальные модели. Для отдельных настроек соединения можно создать `.env.testing` по примеру `.env.testing.example`; ключ приложения возьмите из своей локальной `.env` без публикации. Не запускайте несколько наборов тестов одновременно против одной базы.

`AGENTS.md`, `CLAUDE.md`, `.agents/skills`, `.claude/skills`, `.codex/config.toml`, `.mcp.json` и `boost.json` содержат инструкции, skills и настройки для coding-агентов. Команда `composer boost:refresh` обновляет инструкции и настройки Boost. MCP запускается из корня проекта командой `php artisan boost:mcp`; в Codex конфигурация проекта загружается для доверенного проекта при следующем запуске задачи.

Подробности: [разработка](docs/development.md), [архитектура и ограничения](docs/architecture.md), [оценка и расширение](docs/evaluation.md).

Изменения подготовлены локально. Коммит, push и deploy выполняются только по явной команде пользователя.
